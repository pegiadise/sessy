# sessy

TUI session manager for Claude Code — browse, search, preview, and resume conversations. FOSS Rust CLI on crates.io (`cargo install sessy`), MIT.

**This repo is public** (github.com/pegiadise/sessy). Commits, `CHANGELOG.md` and this file must not carry private info: no internal/employer names, hosts, or unrelated projects. Ask the owner before committing or pushing.

## Commands

```
cargo build              # dev build
cargo test               # unit tests + tests/search_integration.rs (fixtures in tests/fixtures/)
cargo clippy --all-targets  # lint (repo is kept clippy-clean)
cargo +1.86 check --all-targets --locked  # MSRV check (1.86 toolchain is installed)
cargo build --release    # optimized build (lto + strip, see [profile.release])
cargo run -- --all       # run the TUI against all projects
```

- The tree is **not** rustfmt-clean (`cargo fmt --check` fails on `main`). Don't run `cargo fmt` over the whole crate in an unrelated change; format only the lines you touch.
- TUI smoke test without touching the real cache: run in a pty with `HOME=<scratch>` and `CLAUDE_CONFIG_DIR=<scratch>` holding a `projects/<dir>/` with a few `.jsonl` files (e.g. copies of `tests/fixtures/`). Against the real `~/.claude/projects`, the first index build in a fresh `HOME` is slow (a debug build still hadn't drawn after ~20 s).

CLI flags (`src/main.rs`, README): default = sessions for the current project (all projects when the current one has none); `--all`/`-a` (every project); `--project X` (substring filter, implies all projects); `--recent 7d` (1h/7d/2w/1m; invalid values exit with an error); `--rebuild-index` (ignore the cache; not in the README); `--print` (emit the picked session ID for `claude --resume $(sessy --print)`; the TUI renders on **stderr** so stdout stays clean, every pick key prints, quitting exits 1); `--purge` (delete sessions < 15 KB older than 2 days, pinned ones kept; respects `--project`/`--recent`); `--mouse` (mouse capture, also config `mouse`). A resume `exec`s claude on Unix (nothing of sessy's stays in memory; the shell sees claude's status); on Windows sessy waits and exits with claude's code.

## Architecture

```
src/
  main.rs       — CLI (clap), event loop (drains queued events, then searches/redraws once), key routing per focus, post-TUI actions (launch/print/purge)
  lib.rs        — exposes the modules so tests/search_integration.rs can use them
  app.rs        — App state; focus/view modes; sort/scope/size filter; bookmark/search/rename/copy; selection preservation; match-line snippets
  as_written.rs — Background lookup of a match line's text in the transcript, to show it with its original case
  fold.rs       — Search folding: lowercase + Latin/Greek accents dropped + ς→σ; byte-origin maps; accent-tolerant regex
  subagents.rs  — Subagent transcripts (<id>/subagents/agent-*.jsonl + .meta.json description): listing, search text, markers
  ui.rs         — Two-pane ratatui rendering: session list + preview/files + timeline + help overlay + context-sensitive status bar; wrapping helpers
  clipboard.rs  — Copy (pbcopy / wl-copy / xclip / xsel / copypasta / OSC 52) and open-URL
  index.rs      — Filesystem scanner, bincode cache (<cache>/sessy/index.bin), incremental rebuild
  input.rs      — TextInput: single-line editor with movable cursor (search bars)
  live.rs       — Sessions open in a running Claude Code (<config>/sessions/<pid>.json, pid liveness via kill(pid, 0))
  parser.rs     — JSONL single-pass scanner; human message detection; conversation extraction (with optional tool lines)
  session.rs    — SessionMeta struct, formatting helpers (duration, file size, size category)
  preview.rs    — Single background preview worker (skips to the newest request) + FIFO cache (shared `Arc` lines)
  query.rs      — Search box parsing: free text + key:value filters (project/branch/file/is/after/since/before/on)
  text_cache.rs — mmap'd companion (<cache>/sessy/text.bin) holding searchable conversation text (user + assistant + thinking + tool I/O)
  config.rs     — Optional ~/.config/sessy/config.toml (scope, sort, show_tool_activity, enter, density, mouse); parse errors surface in the status bar
  bookmarks.rs  — Bookmark persistence (<cache>/sessy/bookmarks.json)
  trash.rs      — Deleted sessions go to <cache>/sessy/trash/<unix-secs>-<id>/ (undo with `u`; pruned after 7 days)
  export.rs     — Markdown export of session conversations
```

`<cache>` is `dirs::cache_dir()`: `~/Library/Caches` on macOS, `~/.cache` on Linux. The README says `~/.cache/sessy/…` throughout, which is only right on Linux.

## Key concepts and gotchas

- **Claude Code sessions** are JSONL files at `~/.claude/projects/<encoded-path>/<uuid>.jsonl` (`$CLAUDE_CONFIG_DIR/projects` when set). Top-level `agent-*.jsonl` (old subagent transcripts) are skipped
- **Path encoding**: Claude replaces every non-alphanumeric char with `-`, so `/Users/me/code/foo` → `-Users-me-code-foo`
- **Single-pass scan**: `parser::scan_session` reads the whole file once, extracting head meta (title/branch/slug/cwd/first ts), tail meta (last human message/ts/rename), AI title (`type:"ai-title"`), custom title (`type:"custom-title"` — what `/rename` writes today; legacy `/rename` local-command args are the fallback), permission mode, Claude Code version, skills (`attributionSkill`), changed files (`file-history-snapshot` → `trackedFileBackups` + `file-history-delta` → `trackingPath`), PRs (`type:"pr-link"`, also added to tickets as `#N`), recap (`system`/`away_summary`), tickets, and the human message count. Title/`left off` are derived from the human messages it finds — no separate head/tail seek
- **Human message detection** (`parser::human_text`, shared by scan + preview + export): a queued-command attachment the person typed (`type:"attachment"`, `attachment.type:"queued_command"`, `commandMode:"prompt"`, `origin.kind` absent or `"human"`; text in `attachment.prompt`, string or blocks) — Claude Code stores prompts sent while it's busy this way and mostly never as a user turn; `QueuedPrompts` counts one that does come back as a turn once. Otherwise `type=="user"`, not sidechain, no `toolUseResult`, not `isMeta`/`isCompactSummary`/`isVisibleInTranscriptOnly`, `origin.kind` absent or `"human"` (excludes task notifications and peer-session messages), content is a string **or** a block array (text blocks joined, noise and editor-context blocks — `<ide_…>`, `<system-reminder>` — skipped per block; image-only → `[Image]`), not `[Request interrupted by user…]`, and not command noise (`<command-name>`, `<local-command-stdout>`, `<task-notification>`, `<bash-input>`, …) — except a slash command **with arguments** counts as `"/name args"`. Command-only sessions fall back to the slash-command name as title. Titles/left-off go through `parser::one_line` (pasted_content tags stripped, whitespace folded, ANSI/control chars dropped)
- **Folding**: everything search compares goes through `fold::fold` — the text cache (`push_search_text`), the `*_lc` fields, the query and filter values, the preview's per-line copy (`preview_lines[i].1`), highlighting (`ui::find_hits` via `fold_with_origin`) and `as_written::find_in`. Accents are dropped only for Latin and Greek (U+00C0–024F, U+0370–03FF, U+1E00–1FFF) plus loose U+0300–036F marks; ς folds to σ. Folding changes byte lengths (é→e), so anything mapping folded offsets back to the original must use `fold_with_origin`. `as_written` searches the transcript with `fold::unfolding_pattern` (each letter as a class of the letters that fold to it, `(?i)`)
- **Search text** (`parser::for_each_search_piece`, also used by `as_written`): only `user`/`assistant` entries and typed queued prompts. Newer Claude Code also logs `type:"api-request-blob"` entries (system prompt, skill/tool listings, CLAUDE.md, ~half the bytes of a transcript); indexing them made common words match nearly every session. Tickets come from the same pieces (as written, before lowercasing) plus `gitBranch`, not from raw JSON lines; the ticket regex uses ASCII `(?-u:\b)` (Unicode `\b` sent every non-ASCII line to the slow engine)
- **Last active**: `SessionMeta.timestamp` is the last timestamped entry (fallback: mtime); `file_mtime` is only for change detection. Claude Code appends untimestamped bookkeeping (`last-prompt`, costs) weeks later
- **Real format evolves**: before changing the parser, survey real files (`~/.claude/projects/*/*.jsonl`) for entry `type`s and user-content shapes; `tests/fixtures/current_format_session.jsonl` captures the 2026-09 shapes
- **Index cache**: bincode serialized with version header. It uses bincode 2's `bincode::serde` API with `config::legacy()`, which writes the same bytes as bincode 1 (checked against a real 1.4.0 cache), so the 1→2 move didn't need a version bump. A different config or serializer changes the format, so bump `INDEX_VERSION` with it. `INDEX_VERSION` (in `index.rs`) is **9** — bump it whenever `SessionMeta` *or scan semantics* change. `SessionIndex.text_cache_len` must equal text.bin's size on load, else full rescan (guards against a crash or two instances racing). `build_index` returns `(index, changed)`; main saves only when changed. text.bin is append-only between compactions: unchanged sessions keep their offsets, fresh scans are appended (`append_text_cache` checks the size before and after, so a concurrent append falls back to a rewrite), and it's rewritten temp+rename when live text < half the file. Cached offsets are trusted only when text.bin's size equals the cached `text_cache_len`; since an appended and a rewritten layout can have the same size, main holds `index::lock_cache()` (flock on `<cache>/sessy/index.lock`) from load through save and while mapping text.bin, so new instances never interleave (old releases don't lock); one that finds it held says it's waiting (a suspended instance holds it). text.bin can grow to ~2× the live text before compacting. The index itself is always written temp+rename (fsynced first); failed writes remove their temp file and `*.tmp` older than an hour are swept at startup. **Keep `SessionIndex`/`SessionMeta`'s layout as 1.5.0 has it**: old versions decode the whole index before checking the version, so a layout change makes them misread lengths and abort; new state goes beside it (as `resume.bin` does). It's decoded with a size limit: a damaged file (or a layout change without a version bump) reads as a giant length, which would otherwise abort on the allocation at every start. A missing or unreadable projects folder returns an empty index with `changed = false`, so it never overwrites the cache
- **A session's search text** is its own text, then per subagent (by file name) a marker line — `subagents::MARK` (0x01, stripped from all other text) + the folded `.meta.json` description + `\n` — and that subagent's text. `subagents::split` finds the first mark; ranking scores conversation hits 100 and subagent-only hits 40. `SessionMeta.file_mtime` isn't a time any more: it's an FNV hash of the transcript's and subagents' nanosecond mtimes, the subagents' names and sizes, and their `.meta.json` stamps (size + mtime; a description can be written after the transcript), only compared for equality (`file_size` stays the transcript's own size, for display)
- **Resume** (`resume.bin`, `RESUME_VERSION` 2, keyed by transcript path): per session the `parser::Scanner` state after the last whole line, the byte offset there, an FNV hash of the 4 KB before it, the text length from those lines, and the subagent fingerprint (name, size, mtime, description stamp), plus the `text_offset`/`text_len` it goes with (anything else is ignored). A changed session with a matching entry is read on (`scan_resumed`: old text up to `main_len` + new lines + the old subagent part or a fresh one); otherwise read whole (`scan_full`). An unfinished last line is fed to the current result but not to the saved state. Proven equal to a full build on real 700 MB transcripts; there's a test that edits a transcript's start in place to tell a resume from a full read
- **Scope**: `Scope::Current` = sessions whose recorded `cwd` is under the launch project root (nearest `.git` ancestor below `$HOME`, else the launch dir); sessions without a cwd fall back to the encoded dir name. `--project` implies `Scope::All`
- **Rename** (`r`) appends a `custom-title` entry (Claude Code's own format, no timestamp) and restores the file mtime so the session keeps its date slot. On a live session the status warns that Claude Code may write its own name back
- **Session name priority**: custom title (`/rename`) > `aiTitle` > `slug` field > empty
- **View pipeline**: search → scope (cwd vs all) → size filter → sort (exact search matches first, then bookmarked, then by current sort mode: date/size/duration/messages)
- **Exact vs partial search**: a hit is *exact* when the whole query (lowercased, whitespace folded: `App::search_phrase`) occurs as whole words (`contains_whole_words`, Unicode-aware; `_` and `/` count as word chars, so "deploy" isn't whole in "redeploy" or "deploy_all", and a URL/path fragment like "github.com/foo" inside "github.com/foo/bar" is partial) in any field or the conversation text, or the query equals a ticket. `App.exact_matches` (indexed like `sessions`) holds the flags; keep it aligned when sessions are removed. The list highlights the phrase on exact rows and draws a `── partial matches ──` divider in the gap row after the last exact one
- **Live preview**: `parser::read_conversation` reads on from a `ConversationTail` (the transcript's path, byte offset after whole lines, the file size seen at the last read, queued-prompt dedupe, day-rule state) and yields what one whole read would, a new first-day rule included (`first_rule`, an index into earlier lines). Every second `preview::follow_growth` stats `preview_tail.path` (not a lookup by ID: IDs repeat when a project folder is copied) and, past `seen` (so a half-written last line isn't re-read every tick), sends a `more` request; a read-on that panics comes back as "nothing new" with `seen` moved on, never as an empty full load; `App::append_preview` adds the lines in place (cache entry removed first so `Arc::make_mut` doesn't copy), lays out only the new rows (`lay_out_preview_from`), keeps the current match, and stays at the bottom if it was there, else on the same top message
- **Preview cache**: FIFO-ordered HashMap of `CachedPreview` (lines as `PreviewLines = Arc<Vec<…>>`, shared with `App.preview_lines` instead of copied, plus the row layout for the last width), max 10 entries or 256 MB of text, keeping at least the newest. `recompute_preview_offsets` reuses the layout when the cached lines are the shown ones (`Arc::ptr_eq`) at the same width. Toggling tool activity (`T`) clears it so lines re-extract; `PreviewKeep` carries the find query and the top message across that reload. A result for the shown session applies only while `preview_loading` (a duplicate load must not reset the position). `preview_session_id` set ⇒ loaded or in flight; anything that invalidates lines must clear it
- **Preview line role**: `parser::Speaker` (User/Assistant/Tool/Recap); Tool lines only appear when tool activity is on; the latest recap is pinned as line 0
- **Preview rendering**: `ui::message_rows` (newline-preserving, display-width wrapping measured per grapheme as the terminal draws it: `⚠\u{FE0F}` is 2 columns) is the single source of truth for row counts — `recompute_preview_offsets`, match scrolling, and `visible_preview_lines` all call it with `App::preview_body_width()`. `message_rows_marked` finds hits across the rows of one line (rejoined with the space the wrap dropped, or none mid-word), so a wrapped phrase is marked on both rows and scrolled to. A width change goes through `rewrap_preview`, which keeps a visible current match in view, else the top message (`preview_place`). Scroll/offsets are `usize` (long sessions exceed 65k rows); only on-screen rows are built each frame
- **Selection**: search edits reset to the top match; bookmark/scope/size-filter changes and clearing a search keep the selected session (`reselect`). Search runs once per drained event batch (`search_dirty`), so actions that read `selected` from the search input must apply a pending search first
- **Live sessions**: Claude Code writes `<config>/sessions/<pid>.json` (`pid`, `sessionId` = the transcript's file stem, `status` "busy"/"idle", …) per interactive process. `live::scan` keeps entries whose pid is alive; the event loop rescans every 2 s. Enter/`l` on a live session sets `App.confirm_resume` (only `y` proceeds); so does any pick in `--print` mode; `F` (fork) and `p` outside `--print` never ask. `App.live_dir` is `None` in tests
- **Preview terms**: `App::preview_terms` = the find-in-conversation query when typed, else the session search's words. `refresh_preview_matches` recomputes `preview_search_matches` (messages containing any term) and runs after a search, on preview load (cache hit or worker result) and when the find query changes; match indices must never outlive the lines they index (tool toggle, delete, and loads clear them). `preview_search_active` means an explicit find query only
- **Snippets** (match lines): while searching, comfortable rows show `└ match:` with up to `MAX_SNIPPET_PARTS` pieces of the text-cache line(s) around the hits, the best `Together` level first wherever it is: the whole phrase (whole words preferred), else all words within `NEAR` bytes on one line (`find_cluster`), else each word's first hit, words the row already shows giving way. At each level the conversation comes first, then (at the last level) changed-file paths (`└ file:`), then each subagent's part (`└ subagent "<description>":`, its transcript found by matching the folded description via `subagents::find`). Words only in name/project/branch show none (left off stays). Computed lazily for visible rows, cached in `App.snippets` (keyed by real index; cleared on every search, delete and undo). Each part keeps its lowercased `source` piece; `as_written` (one worker thread, requests carrying `snippet_generation` so stale ones are skipped) finds it in the transcript — regex `(?i)` over a JSON-verbatim stretch, read in 8 MB chunks outward from the piece's relative position, each candidate line parsed and re-checked — and `apply_as_written` swaps in the original-case text. Transcripts are read, not mmap'd (a file shrinking under a map is a SIGBUS)
- **Layout**: below `ui::NARROW_WIDTH` (100) columns, or with `z`, only the focused pane is drawn; the hidden preview's geometry is still synced (`sync_preview_geometry`) so match scrolling is right when it appears. Row prefix is 4 columns (selection, pin, live, space); second/third lines indent 4. `Density::Compact` is one row per session; its divider before partial matches takes a row of its own
- **Search filters** (`query::parse`): known keys only; a known key whose value doesn't parse stays text (`on:click`), one with no value yet is ignored. `App::query()` parses on demand; `search_phrase`/`preview_terms`/exact matching/snippets use only `query.text`, so filters are never highlighted. `text_search_active()` (words present) decides relevance sort vs browse sort
- **Day rules**: `extract_conversation_ext` inserts `Speaker::Day` lines ("Tue Nov 10, 2026") before each local day's first message when a conversation spans several days. They're one row (offsets special-case them), never preview matches, prompts or exported
- **Timeline**: `App.timeline_day` (None = today) moves with the arrows, clamped to `timeline_start` (set by the renderer) and today; Enter → `pick_timeline_day` replaces any date filter in the query with `on:YYYY-MM-DD`. Counts follow scope and size filter
- **Prompts and actions target sessions, not rows**: `AppAction` payloads are indexes into `App.sessions` (stable across view rebuilds). The delete prompt and rename record `App.prompt_target` (the transcript path, since session IDs can repeat across project folders) and check it on confirm. While a prompt or rename is open (`view_frozen`), `live_changed` defers (`live_stale`) instead of rebuilding an `is:open` view. A `y` only confirms once the status bar has drawn the prompt (`prompt_seen`), so a `y` in the same burst as the `d` (pasted text) cancels
- **Keystroke pastes**: the event loop reads a whole burst and `handle_burst` dispatches it; only while focus is List or Preview (decided per run, since keys change focus) does `coalesce_typed_pastes` turn a run of ≥4 plain chars, or ≥2 followed by Enter, into one `Event::Paste` (Tabs and Enters inside are text; not one repeated key, not only movement keys, not a leading `/`; a trailing Enter stays a key and lands in the search box). In inputs keys stay keys, so fast typing behaves as typed. Keys typed before the TUI starts are flushed (`discard_type_ahead`, tcflush on /dev/tty)
- **Mouse** (opt-in): a panic hook (`restore_terminal_on_panic`) switches mouse capture and bracketed paste off (plus raw mode/alt screen for the stderr TUI), on the main thread only; the preview and `as_written` workers `catch_unwind` and carry on. The wheel never wraps (`scroll_list`); motion events don't redraw; a click arriving with a search still pending is dropped (stale geometry); `list_rows` stops at the list's inner height. The renderer records `search_area`/`list_area`/`preview_area` (zeroed each frame, so hidden panes can't be hit), `list_rows` (y → index into `sessions`, so a click after a reordering key in the same burst still hits the session drawn there) and `timeline_cells`; `main::handle_mouse` hit-tests against them. Double-click = 400 ms on the same row
- **Delete**: with `App.trash_dir` set (main), deletes move the transcript + companion dir into the trash and push an undo entry (meta + pin); `None` (tests) deletes for good, and so does a trash that can't take the file (the status says so). A failed undo goes to the bottom of the stack. `--purge` always deletes for good; `main::purgeable` counts the companion `<id>/` folder (subagents, tool output) toward the 15 KB and skips pinned and live sessions, and after the `y` it re-reads pins and live sessions and re-stats each file (kept when it changed). On Windows there's no live check, so the prompt says to close Claude Code first
- **Config validation**: `config::parse` reads the file as a `toml::Table` and takes each key on its own, so a wrong type drops only that key; `Config::problems` names unknown keys and values outside the documented ones in the startup status; `enter_is_yolo` is true only for exactly `yolo`. A file that isn't TOML or can't be read (anything but NotFound) gives `Config::safe_defaults` (Enter safe): it may have said `enter = "safe"`
- **Pins**: `bookmarks::update` re-reads the file, applies the one change and writes temp+rename, so two instances don't drop each other's pins; an unparsable (or non-UTF-8) file is renamed `bookmarks.json.bad`; one that can't be read isn't written (`update` returns `None`, the status says the change isn't saved). `--purge` uses `bookmarks::load_strict` and refuses to run on any read or parse error
- **Stdout hygiene in `--print` mode**: crossterm's kitty-keyboard probe writes its query to stdout when it can't write /dev/tty, so the probe only runs when stdout is a terminal. Anything else that talks to the terminal (OSC 52) goes to /dev/tty

## Release / publish

Every version needs a `CHANGELOG.md` section; that section *is* the GitHub release body. Never use `gh release create --generate-notes`: it only lists merged PRs, and this repo commits straight to `main`, so the notes come out empty.

1. Add the version's section to `CHANGELOG.md` (Keep a Changelog: Added / Changed / Fixed, user-facing wording, nothing private) plus its compare link at the bottom.
2. Bump `version` in `Cargo.toml` (and the release line under Status above).
3. Commit (conventional commit) and tag: `git tag vX.Y.Z`.
4. `cargo publish` from clean git state. The crates.io token lives in `~/.cargo/credentials.toml`.
5. Push commits + tags to `main` (github.com/pegiadise/sessy) — confirm with the owner first.
6. `gh release create vX.Y.Z --title vX.Y.Z --notes-file <(scripts/release-notes.sh vX.Y.Z)`. To fix an existing release: `gh release edit vX.Y.Z --notes-file <(scripts/release-notes.sh vX.Y.Z)`.

History quirks (don't "fix" them): 0.1.0–0.1.9 and 0.2.0–0.2.2 were published without tags; the `v1.0.0` tag points at a release commit that never landed on `main` (1.0.1 is the same code).

## Conventions

- Tests must not touch the user's real cache/config: `App.bookmarks_file` is `None` in tests (persistence off); main sets it
- No `unwrap()` in non-test code — use `ok()?`, `unwrap_or_default()`, or `unwrap_or_else()`
- Parallel scanning with rayon, background preview with std::sync::mpsc
- Status bar keybinding style: Cyan bold key + Rgb(180,180,180) description on Rgb(40,40,40) bg
- Body text uses the terminal's default foreground (`Style::default()`), never `Color::White`, so light themes stay readable; explicit colors only on explicit backgrounds
- Size categories: quick <1MB (green), medium 1-10MB (yellow), deep 10-30MB (magenta), massive >30MB (red)
- Filter out `gitBranch: "HEAD"` — it's noise from detached HEAD states
- Timeline heatmap uses GitHub-style green color scale
- Bookmarked sessions float to top of any sort order (below exact matches while searching)
- List/preview key handlers ignore Ctrl/Alt/Super combos except explicit ones (Ctrl+N/P/D/U/F/B); Ctrl+C quits from any focus; Ctrl+V/⌘V (as a key) reads the clipboard from any focus; a paste outside an input replaces the query and searches; delete confirms only on `y`. Windows has no paste events (crossterm), so Windows Terminal's Ctrl+V arrives as keystrokes
